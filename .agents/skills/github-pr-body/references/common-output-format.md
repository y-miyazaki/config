# Output Format Specification

Use one of the following structures for PR Body output.

```markdown
## Overview

<Baseline mode: metadata-only content generated by pr_body.sh (Title, Branch, Stats) — keep as generated. Full-body mode: replace it with a 2–5 sentence summary of what changed and why, without metadata visible in GitHub UI (branch names, file counts, PR numbers).>

## Changes

### Config

- **path/to/file.tf**: +N / -M lines

### Docs

- **path/to/README.md**: +N / -M lines

### Feature

- **path/to/source.go**: +N / -M lines

**Summary**: N files changed (+A / -D lines)
```

`pr_body.sh` emits one `### <Type>` subsection per classification present (Config, Docs, Feature, Test, Other) with one `- **<path>**: +A / -D lines` bullet per file, then a `**Summary**` line. When more than 30 files changed, each subsection heading carries totals (`### Config (N files, +A / -D lines)`), lists the first 5 files, and ends with `- ... and K more files`. Keep this script output as is.

For full AI completion after baseline generation, output the complete PR body including every template H2 that carries guidance comments or examples (e.g. `## Testing`, `## Checklist`).

## Rules

- Output ONLY the updated `## Overview` and `## Changes` content blocks when preparing baseline-only content.
- Output the complete PR body when preparing content for `pr_body.sh --body-file`.
- Preserve all other existing PR body sections verbatim.
- Restore empty template sections that exist in the PR template but are missing from the current body.
- If `--body-file` is used, include the final visible content for all sections the AI completed.
- In `## Changes`, keep the script-generated classification and line counts.
- Baseline mode: the metadata-only `## Overview` from `pr_body.sh` (Title, Branch, Stats) is valid; do not edit it.
- Full-body mode: replace the baseline `## Overview` with narrative content and omit GitHub UI metadata (branch names, file counts, PR numbers).
- `## Changes` lists every changed file, except the summarized form above 30 files.

## Classification Labels

| Label   | When to Use                                     |
| ------- | ----------------------------------------------- |
| Config  | Infrastructure, CI/CD, tool configuration files |
| Docs    | README, documentation files                     |
| Feature | Source code implementing functionality          |
| Test    | Test files, test fixtures                       |
| Other   | Scripts, generated files, miscellaneous         |
