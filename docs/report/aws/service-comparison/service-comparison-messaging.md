### Guidelines

**→ SQS を標準のメッセージキューとして採用する。** サーバーレス、従量課金、DLQ 内蔵で運用負荷が最も低い。

- リアルタイムストリーミング (ログ集約、クリックストリーム) でリプレイ・複数コンシューマーが必要 → Kinesis Data Streams
- 大規模イベントストリーミングで Kafka エコシステム (Connect、Streams) を活用したい → MSK
- 順序保証 + 重複排除が必要な場合は SQS FIFO を採用 (スループット制限に注意)
- MSK は最小コストが高いため、小〜中規模では Kinesis を推奨
- Kinesis Data Streams の On-demand Advantage はストリーム時間課金がなく、US East の取り込み \$0.032/GB・取り出し \$0.016/GB (Enhanced Fan-Out 追加課金なし) だが、アカウント全体で 25 MB/s の取り込み・取り出しの最低コミットが必要 ([料金](https://aws.amazon.com/kinesis/data-streams/pricing/))。集約 10 MB/s 以上で検討する
- MSK には Standard ブローカーに加え Express ブローカー (ストレージ無制限) と MSK Serverless (クラスターあたり取り込み 200 MBps、取り出し 400 MBps) があり、クラスタータイプで上限が異なる ([Quotas](https://docs.aws.amazon.com/msk/latest/developerguide/limits.html))

### Guidelines

**→ イベント駆動アーキテクチャには EventBridge を標準採用する。**

- AWS サービス間のイベント連携、スケジュール実行 → EventBridge
- シンプルな Fan-Out (1 つのイベントを複数 SQS キューに配信) → SNS + SQS
- 非同期タスクキュー (ワーカーパターン) → SQS
- EventBridge → SQS の組み合わせ: イベントフィルタリング + 確実な処理を両立するパターンとして推奨
- SNS → SQS (Fan-Out) パターンは引き続き有効。EventBridge で代替可能だが、既存構成の移行は不要
